# 独立轻量 UX 走查

评审入口：专用临时 Android 模拟器 emulator-5580，io.github.kuaishou.filter/.ui.MainActivity。仅读取 UX 走查指引及真实界面，未读项目源码、设计说明、原始任务、其他评审或测试用例。

## 产品理解

这是给想自行控制视频评论内容的人使用的评论过滤设置工具。用户按关键词、IP 属地或用户性别设置规则，选择隐藏命中内容或只保留命中内容。首页说明只处理视频主评论；进入使用说明后确认目标是快手评论区。

## 自选主任务与结果

任务：让包含 spam 的主评论被黑名单隐藏，并确认配置保存。

结果：配置任务完成；评论实际隐藏结果未验证，因此端到端任务为部分完成。没有因界面导致卡住或走错。

| 步骤 | 看到什么 → 为什么操作 → 实际发生什么 |
| --- | --- |
| 1 | 首页默认黑名单，说明“隐藏命中的评论”，规则数为 0，过滤关闭 → 需要先添加待屏蔽关键词 → 点击底部“添加规则”打开表单。证据 01、02。 |
| 2 | 名称标为可选，出现“评论关键词”“每行一个”，底部说明留空不限、填写条件同时满足 → 仅填写 spam，其余留空 → 输入值显示在关键词栏，完成按钮可见。证据 03。 |
| 3 | 点击“完成” → 期望保存并返回列表 → 列表显示“黑名单规则 · 1”“规则 1”“关键词 · spam”，规则默认开启。 |
| 4 | 顶部过滤总开关仍关闭 → 需要启用整个过滤功能 → 点击后开关开启；底部显示“已自动保存 · 刷新评论区生效”。证据 04。 |
| 5 | 底部提示需要刷新评论区 → 想确认生效范围与最后步骤 → 点保存提示没有出现新的说明；再经“更多 → 使用说明”，读到“仅过滤主评论。修改后刷新快手评论区。”说明同规则条件同时满足、多规则任意一条即可。证据 05、06、07。此处没有卡住，说明足以给出接下来的动作。 |
| 6 | 需要确认自动保存 → 关闭并重新启动该设置应用 → 总开关开启、规则开启、spam 内容和规则数 1 均保留；点击规则卡片可重新进入编辑，随后返回。证据 08、09。 |

完成反馈明确：新规则立即在列表出现，内容摘要与数量可核对；总开关及单条规则开关有可见状态；保存提示说明后续刷新动作。未观察到持续等待或失败状态。

## 验证限制

- 未打开或操作快手，未使用网络，因此未确认实际评论过滤、目标应用运行状态或模块激活状态。
- 使用 ADB 输入 ASCII 关键词。模拟器该次输入未出现软键盘，未验证软键盘遮挡、中文输入法或键盘完成键。
- 未验证多条规则、多个关键词/属地、白名单、删除、无效输入及大字体/屏幕阅读器。
- 未验证声音、触觉和真机手感，不作通过结论。
- 模拟器保留测试数据：黑名单规则 1 条，关键词 spam；总过滤与该规则均开启。
