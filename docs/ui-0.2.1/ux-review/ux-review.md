# 轻量 UX 走查

日期：2026-10-29。环境：emulator-5580，Android API 37，1280×2856，density 480。仅操作 `io.github.kuaishou.filter/.ui.MainActivity` 的真实页面，未读项目源码、历史设计或现有报告。

## 产品理解与自选任务

这是给短视频应用设置评论显示规则的模块配置工具。最可能使用它的是希望少看到特定内容、按自己的条件筛选主评论的人。首页先选择应用，再设置过滤开关、黑白名单和规则。

我选择的任务是：**在快手中屏蔽含 `spam` 的主评论，并确认配置已经保存、知道怎样让它生效。** 选择关键词是因为首页空状态直接引导添加属地、关键词或性别条件，关键词能形成一个明确、可检查的单条件规则。

结果：**部分完成。** 本地添加、启用、保存和重启后的配置保留均完成；实际快手评论是否被过滤没有验证。没有打开快手、LSPosed 或执行任何外部应用网络操作。

## 关键问题（1 条）

### “已保存”之后，生效所需的下一步藏在使用说明中

**观察到的事实：** 在隔离后的首次配置路径中，打开总过滤开关并保存后，页面只显示开启的开关与“快手规则已保存”反馈（09-save-feedback.png）。该路径没有显示刷新评论区、LSPosed 勾选或重启目标应用的提示。打开右上角“更多”，再进入“使用说明”，正文才说明：“修改后点击保存规则，再刷新对应应用评论区。首次启用需在 LSPosed 勾选对应应用并重启该应用。”（11-help.png）。这是完成配置后确认下一步时实际出现的犹豫，不能据此断言模块当时未激活或过滤失效。

**原因推断：** 用户在“启用过滤”与“已保存”之后容易认为任务已经完成；实际生效的前提和刷新操作没有出现在这一动作附近，需要用户主动找说明。页面也没有可观察的目标应用生效结果来消除这份不确定性。

**建议达到的结果：** 用户首次启用或保存后，能在当前上下文知道后续需要做什么，例如清楚提示刷新目标应用评论区，并提供首次启用所需步骤入口。即使无法检测激活状态，也应让“配置已保存”与“接下来需要完成的操作”同时清楚可见。
