日期：2026-10-31。包名与签名保持不变，versionCode 14。

## 抖音真实数据入口

设备安装的抖音 40.9.0 / 400901 与用户原 APK 的 SHA-256 一致：`bad30e22688238a118f360138fe82da3c6346be84b43b23a16681a168680f6b0`，没有额外 split。设备原模块也与已交付 0.2.5 完全一致，排除了安装错包和同版本不同 APK 的问题。

最初状态为 READY、读取/隐藏计数均为 0。读取模块配置确认过滤开启且有有效规则；LSPosed 表明四个传统 consumer 安装成功、配置加载成功，但有界诊断始终没有入口命中。真实 Activity 的 Fragment 栈显示 `PadSplitCommentListPageFragment` 内活动子页为 `KmpCommentListFragment`。结合原 APK 的独立 KMP 数据链，确认这次遗漏的是实际分支，而非规则没有保存或关闭。

新增入口从稳定 `KCmtListViewModel` 的无参 getter 返回类型中，唯一定位 `(enum, CommentItemList) -> void` 的数据源消费方法。实际解析结果为 `X.0SPh.LIZ(X.0RzE, CommentItemList)`，不把这两个混淆名称写入选择器。只对参数 1 的响应做副本过滤，参数 0 的请求枚举、原列表、游标、总数和 hasMore 保持原样；传统路径继续保留。更多类型约束与测试见 [KMP 修复说明](DOUYIN_KMP_FIX.md)。

修复构建在同一真实设备上观察到新入口连续命中两批各 20 条主评论，聚合读取 40 次、隐藏 38 次，runtime/install/config 错误均为空；屏幕上观察到只保留符合既有白名单的评论。一次列表内向上滑动后仍是该计数，不能据此声称原生加载更多已通过验收，也没有新增自动补页行为。

这些是该设备、该 APK 与既有规则下的观察，不保证独立详情、直播/电商、其他实验分支或未来所有版本。实际原始日志、屏幕、配置备份只存于忽略目录 `.tools/device-debug/`；本仓库仅保存类名、计数和错误类型的摘要，不提交评论正文、作者/设备 ID、实际属地规则或账号数据。

## 小红书性别过滤移除

用户在诊断后明确要求直接删除性别过滤。本次不再继续改资料接口或放宽身份关联。

诊断时收到的回调类型确为 `UserInfo`，但命中 `AUTHOR_MISMATCH`，约 156–158ms 返回，不能归因为超时或绑定失败。保护逻辑没有将不匹配资料的性别用于请求作者；也没有为让匹配通过而把请求 ID 强行回填。该观察只解释当时失败的位置，不代表已经修好资料接口。

移除内容：

- 删除独立开关及规则编辑中的性别选项，帮助说明改为小红书仅支持属地和关键词。
- 删除宿主资料服务/Rx 订阅、缓存、并发任务、超时和资料诊断；不再绑定评论作者的 user/userid 字段，不再额外查询资料。
- 小红书统一以 `evaluate(comment, false)` 执行规则。纯性别规则暂停，混合规则按剩余条件执行；空或无有效条件的白名单保持原有显示全部策略。
- 保留旧规则中的性别数组作为历史数据，避免破坏规则或把纯性别白名单误变为空条件匹配。读取时移除过时的 root `resolveProfileGender` 开关，但不自动写盘；手动保存时才清理旧开关。核心 JSON 解析器保留对此旧键的兼容接受，任何适配器均不通过它发起资料请求。
- 原生文本/属地投影、包装行、展开/收起回复归属处理、删除操作隔离与配置刷新保持生效。
- 其他应用的原生性别过滤和表单不受影响。

历史的资料性别设计见 [0.2.1 记录](XHS_GENDER_0.2.1.md)，不代表当前版本保留该功能。

## 验证与交付

更新后的运行状态 Binder、持久化、通知去重、异常类别、宿主隔离、过期会话、非法输入、规则不可写及升级作用域检查通过，等待/读取成功/部分异常/适配失败/更新后等待验证界面通过，见 [状态回归结果](runtime-status-0.2.6/results.json)。这些测试使用无代码宿主包占位，不作为真实 Hook 兼容证明；测试偏好与模拟器设置已恢复。模拟器安装包 SHA-256 与交付 APK 一致。
