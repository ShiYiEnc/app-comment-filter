# 抖音空页补页修复 0.2.7

日期：2026-10-31。基准 APK 仍为抖音 40.9.0 / 400901，普通 DEX/JADX/smali 分析复用上一版匹配的 APK，不将普通静态输出称为 REA Evidence。真机通过 ADB 与 LSPosed 有界日志独立验证。原始屏幕、日志和偏好备份保留在忽略目录 `.tools/device-debug/`，不提交评论正文、账号、作者、视频 ID、具体规则值、游标或设备序列号。

## 原因

真机中 KMP 首屏 20 条保留 2 条、追加 20 条保留 1 条，接着 20 条全部被过滤。数据源的完成回调仍被执行，返回 0 条 UI 行，随后原生预取不再自动请求下一页。手动点击会再次读取，但再次全被过滤时，看上去仍没有变化。

静态对应关系：

- `X.0SPh.LIZ(enum, CommentItemList)` 的空列表分支仍派发追加成功事件；`X.0SPz.LIZ` 最终调用数据源唯一的 `void(List)` 完成入口，空列表也会完成 Deferred。
- `com.bytedance.kmp.klist.KListViewModel` 的结果 collector（`Y.AFCollectorS1082S0100000_16` 的该分支）按 nextKey 设置 HAS_MORE，再把请求状态恢复 IDLE。成功处理不要求可见列表非空。
- 因而底部“加载中”文案不能单独证明网络请求没有完成。本例为过滤后的可见行未增长，预取触发条件没有再次变化。

这是实际数据入口已修复后的分页缺口，不再通过增加一个读取 Hook 或修改版本限制解决。

## 实现

保持 0.2.6 响应副本过滤边界，保留服务器响应原件、游标、hasMore、总数等信息。补页作为独立可选能力安装：

1. 以稳定 KListViewModel 的数据源构造参数建立 source→pager 弱关联，以 KCmtListViewModel 返回源对象的 getter 建立 source→owner 弱关联。弱值避免 pager 对 source 的引用将弱键间接保活。
2. 只在过滤开启、原始页非空、过滤后为空、服务器仍有下一页且游标未重复时准备继续。只有原生完成回调成功后才调度。
3. 等待原生 pager 请求状态 IDLE 且页脚为 HAS_MORE，调用它原有的 `Uj()`；不直接写分页状态，不重试 ERROR，不伪造非空列表。
4. 检查 UI owner 为 RESUMED、评论面板仍显示、source/面板各自的会话标识未变化，以及规则快照仍一致。预加载没有 UI owner，不自动请求。面板显示状态来自 KCmtListPanelViewModel 的 pageUiState 唯一 boolean；源会话标识与面板标识分别比较前后，不能假设两者字符串相等。
5. 一轮最多自动请求 5 个额外页。出现可见评论就交回原生滚动；末页、服务器空页、重复/循环游标停止。达到上限提示用户点击原生底部继续；原生点击开始新一轮预算，保留原有点击回调和页脚样式。严格规则确实没有匹配时，仍不会显示被过滤评论。
6. 刷新、配置变化、ViewModel 清理及新响应使旧票据失效。每个票据仅可发起一次请求；原生请求尚未空闲时仅短暂等待，不并发发请求。

补页的类/字段/方法结构不兼容时，回滚该可选组，继续保留 KMP 核心过滤、经典分支和原生手动分页，并报告“自动补页异常”。分页运行错误取消旧票据，独立归类；不会误记成核心评论处理错误。

## 验证

真机观察到连续空可见页后原生自动补页 1–5 次并停下；之后的原生手动触发可开始下一轮。另一次观察到空可见页后自动请求，下一批 20 条中保留 1 条，完成回调返回 3 条 UI 行（包含原生回复/控制行），恢复可见追加。运行及分页错误为空。这些是当前设备、KMP 页面及既有规则的验证，不涵盖全部实验分支、独立详情或未来版本。

单元测试覆盖多空页后出现可见评论、5 次预算及手动继续、完成前不请求、重复完成不并发、重复/循环游标、刷新/取消/旧票据、服务器空页/末页/关闭过滤/其他请求类型，以及日志不含游标或评论值。最终安装包身份、测试统计和真机记录见 [build-0.2.7.json](build-0.2.7.json)。

最终交付包在真机再次验证：首屏及原生追加之后，自动跨过 4 个空可见页，到第 7 批服务器明确返回 hasMore=false 即停止。聚合读取 140、隐藏 134，runtime/pagination/install/config 错误为空。安装包 SHA-256 与交付文件一致；5 份既有规则 XML 与调试前备份逐一比较，内容未改。共 164 项单元测试通过（app 102、core 62），lint 仅保留原有两项警告。关闭面板/生命周期竞态、网络错误和其他实验分支未逐一做真机故障注入，不扩大验证范围。

原生 HAS_MORE 页脚文案/动画保留；达到补页上限时的说明通过 Toast 提示，系统可能限制 Toast。仍无匹配时可点击底部继续查找，不将其伪装成“服务器没有更多评论”。
